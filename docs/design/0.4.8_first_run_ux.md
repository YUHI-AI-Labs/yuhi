# v0.4.8 — Minimal First-Run UX (Phase 6)

## Scope

The directive's ask: a Privacy Mode selector in the first-run flow ("Prepare → Privacy
Mode → Start Claude Code only"), "Repository Optimization" collapsed into "Advanced",
a redesigned normal CLI summary, `--verbose` detail preservation — explicitly NOT a
full Yuhi Mode panel redesign (deferred to v0.5.0).

Research before writing code (`apps/vscode/src/extension.ts`'s welcome/first-run
sequence, `apps/vscode/src/activity-panel.ts`'s "Repository Optimization" rendering,
`apps/cli/src/index.ts`'s `prepare` action) found:

- VS Code's actual first-run toast (`extension.ts`, gated by a `workspaceState` key)
  was ALREADY minimal — a one-line "Prepared Workspace opened" notification with a
  single action button, no Repository Optimization stats in it. Nothing to trim there.
- "Repository Optimization" lives entirely in `activity-panel.ts`'s PERSISTENT Activity
  Bar dashboard, rendered as the headline of every panel state (`not-prepared`,
  `preparing`, `yuhi-mode`, `ready`) — this **is** the "Yuhi Mode panel" the directive
  says NOT to redesign this phase, not a first-run-only element.
- There was no Privacy Mode selection UI anywhere in VS Code for Static Prepare (only
  the Dynamic Terminal/Native GUI setting built in Phase 4, a different surface).
- `yuhi prepare`'s normal-mode output was ~40–55 lines; the existing global `--verbose`
  flag added nothing to a successful `prepare` run (it only dumped stack traces on
  unexpected errors).

## Decisions

**"Repository Optimization collapsed into Advanced" is scoped to the first-run flow,
not `activity-panel.ts`'s persistent dashboard.** Restructuring a multi-state,
heavily-used panel (rendered on every subsequent open, not just first run) is exactly
the "full Yuhi Mode panel redesign" the directive excludes. Since the actual first-run
toast never showed Repository Optimization stats in the first place, this line item
was already satisfied by the existing design — recorded here rather than silently
skipped, so it isn't mistaken for unaddressed scope.

**Privacy Mode selection is a genuinely new UI element**, built as a one-time VS Code
QuickPick inserted into `commandPrepareAndStartClaude`'s existing flow (target agent →
source folder → **Privacy Mode (first run only)** → prepare → Claude Code) — the exact
sequence the directive names. The choice is written to a new `yuhi.privacyMode` setting
(global scope: a first-run choice is a preference for the whole installation, not one
folder) and resolved through the SAME `resolvePrivacyPolicy` (`@yuhi/shared`) the CLI's
`prepare` command already uses, so Static Prepare's Privacy Mode resolution has exactly
one implementation across both surfaces, not two that could drift. Dismissing the
picker (Escape) is treated as "accept Balanced" and still marks first-run as done — a
first-run polish step must never become a recurring interruption.

**The CLI summary redesign reuses the existing global `--verbose` flag** rather than
introducing a second, colliding flag with the same name and a different meaning.
Before this phase, `--verbose` did nothing for a successful `prepare` run (only for
crash stack traces); now it also gates which of the two report shapes prints. This
satisfies "`--verbose` detail preservation" literally: the OLD ~40-line report is
preserved byte-for-byte behind the flag, not shortened or removed.

## What shipped

### VS Code

- `yuhi.privacyMode` setting (`apps/vscode/package.json`) — `""` (inherit
  `yuhi.yaml`'s `privacy.mode`, else Balanced) / `balanced` / `strict` / `trusted-local`.
- `resolvePrivacyModeForLaunch(root)` (`extension.ts`) — precedence: setting >
  `yuhi.yaml` `privacy.mode` > Balanced, via `resolvePrivacyPolicy`. Trusted Local
  requires confirmation through the SAME `confirmTrustedLocalForWorkspace` helper
  Phase 4 built for Dynamic Terminal/Native GUI (one confirmation UI, one
  workspace-scoped acknowledgement key per surface, not a new dialog design).
  Returns `undefined` (after showing the reason) on resolution failure — the caller
  (`prepareWorkspaceForLaunch`) aborts preparation rather than silently falling back.
- `ensureFirstRunPrivacyModeChoice(context)` — the one-time QuickPick, gated by
  `context.globalState.get("yuhi.firstRunPrivacyModeShown")`. Wired into
  `commandPrepareAndStartClaude` between picking the source workspace and starting
  preparation.
- `prepareWorkspaceForLaunch` now resolves and threads `privacyMode` into
  `prepareWorkspaceOutcome(...)` (the `@yuhi/core` `prepareWorkspace()` wrapper) —
  Static Prepare in VS Code was previously always implicitly Balanced with no way to
  change it; it now genuinely varies by the resolved mode, same as the CLI.

### CLI (`apps/cli/src/index.ts`, `prepare` command)

- Default (non-`--verbose`, non-`--json`) output redesigned to:
  ```
  ✓ Workspace prepared
    Privacy: Balanced
    Files: 42 available · 3 excluded · 1 with a warning
    Reduction: ~62%
    Run ID: <runId>

  Start Claude Code:  yuhi launch claude --run <runId>
  Full details:       yuhi prepare --verbose
  ```
  (~8 lines instead of ~40–55). Manually verified against a live build for the
  default, `--verbose`, Trusted Local, and `--json` cases before writing automated
  tests (see below).
- `--verbose` preserves the FULL previous report unchanged (banner, `Repository
  Ready`, `Context preparation`, Yuhi Mode summary, workflow/run diagnostics — every
  line that existed before this phase, byte-for-byte).
- The pre-existing standalone `Privacy: <mode>` line (added in Phase 2, printed BEFORE
  `prepareWorkspace()` even runs) is now gated to `--verbose` only, since the new
  default summary already includes it — without this the line printed TWICE
  (discovered and fixed during manual verification, before any test was written). The
  Trusted Local warning body still prints unconditionally in both modes: it is a
  safety disclosure shown before a potentially long run starts, not a summary line.
- `--json` output is untouched (verified explicitly; it was already a separate,
  complete path per the research).

## Tests

- 4 new CLI end-to-end subprocess tests (`apps/cli/src/prepare-summary-cli.test.ts`):
  default summary shape, `--verbose` preserves the full report and does NOT also print
  the concise summary, Trusted Local's warning appears in both modes, `--json` is
  unaffected. Includes an explicit assertion that `"Privacy:"` appears exactly once in
  default-mode output (regression guard for the duplication bug found and fixed during
  manual verification).
- VS Code: no new automated test for `resolvePrivacyModeForLaunch`/
  `ensureFirstRunPrivacyModeChoice` themselves — they live in `extension.ts`, which
  (consistent with the rest of that file) has no dedicated unit test file in this
  codebase; the full `apps/vscode` suite (233 tests, covering `launch.ts`,
  `activity-panel.ts`, `dynamic-context.ts`, etc.) was re-run and passes unmodified,
  confirming no regression to the modules that ARE tested.
- Full monorepo suite: 1449/1449, zero flakes (the two previously-observed
  intermittent flakes — the CLI build race fixed in Phase 4's globalSetup change, and
  a timing-sensitive concurrency test — did not reproduce in this run).
