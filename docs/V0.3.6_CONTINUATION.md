## 0. Product principle for v0.3.6 (the bar every change is measured against)

> Yuhi doesn't make the user wait. What it can't understand it doesn't stop — it includes it
> **with a warning**, inspects in the **background**, and reduces tokens as much as possible
> **while keeping the repository understandable**. Disclose uncertainty honestly. Let the user decide.

Yuhi is **not** a fail-closed product and **not** merely a token-saver — it is **Repository
Optimization**. Concretely (already in `CLAUDE.md`): Balanced/Strict include unverified
PDF/DOCX/PPTX/unknown **available-with-warning** (`originalShared: true`); only known
credentials / private keys / explicit policy-blocks are masked/excluded; Maximum Privacy keeps
originals local. Foreground does **zero** heavy processing; PDF/OCR/summarize continue in the
background and publish verified companions.

## 5. Conventions & invariants (do not break)

- **Security invariants** (from `docs/CODEX_HANDOFF.md` §6): raw secrets/PII never delivered;
  originals of PDF/DOCX/PPTX never shared (only sanitized companions); source repo never modified;
  private background state stays outside the agent-visible root (public `background-status.json`
  only); safe argv spawn; no abspath/env/raw-error/secret in any public surface.
- **Single source of truth**: every count comes from the Core `YuhiModeSummary` — no surface
  recomputes.
- **Honest metrics**: null → "Not measured"; never a faked `0`; show the real % even if tiny; label
  it exactly "Estimated context reduction"; never call it billing/API/cost savings; separate
  repository-representation estimates from actual agent usage.
- **Git**: commit only on green; author YUHI-AI-Labs, no Claude/personal trailer. **Push is
  approved**; **npm/Marketplace publish is NOT** — only after the full gate + explicit go-ahead,
  and the published commit + VSIX/npm SHA must match.
- **Orchestration lesson from this session**: run agents on **disjoint files**, ideally
  **sequentially**, and get a green commit between phases — concurrent edits to shared files
  (e.g. `activity-panel.ts`, `prepare-workspace.ts`, barrel `index.ts`) clobber and produce false
  test failures. `prepare-workspace.ts` should have a single writer per phase.
